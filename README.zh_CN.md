# Tachi Badge

把 [tachi](https://github.com/monsterxx03/tachi) 的「等一下」搬到 AI Passport 这块小屏上。

## 它解决什么

tachi 干活时会停下来等人两次：一次是它要执行一条被判为「需要确认」的命令，一次是它有个
问题要问你。这两种等待平时只出现在电脑屏幕上——人一旦离开电脑就看不见了。

这个固件让 AI Passport（240×320 的小屏 + 三枚按键）成为那个等待的第二个入口：屏幕告诉你
「谁在等你、等什么」，按键替你把决定送回去。

## 四块屏

| 屏 | 什么时候出现 | 能做什么 |
| --- | --- | --- |
| 状态屏 | 平时 | 看谁在跑、跑到哪一步、连没连上电脑、电量；顶栏还写着此刻走的是蓝牙还是 USB |
| 确认屏 | 有一条命令要放行 | 看命令预览，选「允许一次 / 本会话允许 / 拒绝」 |
| 问答屏 | 模型提了问题 | 选项列表，支持多选 |
| 配对屏 | 第一次用蓝牙 | 屏上那 6 位码，照着敲进电脑 |

配对屏压过其它三块：码在屏上的时候，你唯一的任务就是把它敲进电脑，别的信息全是干扰。

按键：上/下短按在选项间移动，确定提交。多选的问题用确定切换勾选、长按提交；一次问多题时，
**长按上/下**在题与题之间切换（单选题答完会自动进入下一题）。**题面长到装不下时长按上/下先翻屏**
（一次一屏，3 行），翻到那一端才轮到换题；正文放得下时行为完全不变。状态屏上确定长按是
**忘记那台电脑**（按两次，第一次只是问你一句）。

屏幕会自己闲下来：没有待答项、也没人按键时，60 秒后背光熄灭。省电靠的是背光，不是让芯片睡下去
——睡下去就听不到主机递过来的 ask。**有待答项时永不熄屏，正在配对时也不熄**（那 6 位码就是此刻的
任务，而人正站在电脑前敲它）；灭屏后按任意键立刻亮，而那一次按键
只负责点亮，不会提交任何东西（黑屏上你看不见光标在哪一项）。收到新的待答项、或者链路断开，
屏幕也会自己亮起来。

选项放不下时不再只是打点：**选中的那一行**会横向循环滚动显示全文，其余行保持打点。只有选中那行
滚，是因为五行同时滚谁也看不清；熄屏时动画会停掉——黑屏背后滚动的文字只是在烧电。

**放不下的东西会说出来**，而不是悄悄少一项：选项太多时显示 4 项 + 一行「…还有 N 项在电脑上」；
题数超上限、或某道题长得装不下时弹一句「还有 N 题没上屏，到电脑上答」（答完眼前这几题就提交的话，
模型会收到一个少了几条的答复，所以这件事必须让人知道）；答案大到装不下时也说一句，而不是按下去
毫无反应。

## 它怎么和电脑说话

一条链路：USB 串口（设备侧是 ESP32-C3 的 USB-Serial-JTAG），或者不插线的蓝牙。两者走同一份协议
——行分隔 JSON，每行以 `@@` 开头，所以换传输不改一个字。

蓝牙那条第一次要配对一次：设备屏上给出 6 位码，你在电脑上敲进去（之后重连免配对）。

前缀不是洁癖：串口上设备的控制台日志和协议共用同一条线，前缀是唯一能把两者分开的东西——
设备启动时那几行 `I (156) esp_image: ...` 和 `@@{"t":"hello"...}` 就是交错在一起的。

协议的另一半在 tachi 仓库：`desktop/link/link.go`；设计说明在
`docs/2026-09-28-agent-badge-link-design.md`（那份文档记录了这个东西为什么长这样，
以及本地实测到的几个约束）。

## 构建

需要 ESP-IDF 5.5.3。

```bash
. ~/esp/esp-idf-v5.5.3/export.sh
idf.py build
idf.py -p /dev/cu.usbmodem2101 flash
```

### 头像（已入库）

状态屏中间是 tachi 的头像（不再是那个占位色的圆）。它同样是生成物，但**随仓库分发**
（`main/badge_avatar.c`，180 KB），所以克隆下来直接就有；只有换头像时才重新生成：

```bash
uv run tools/mk_badge_avatar.py        # 依赖写在脚本里，uv 自己准备环境
```

默认读 `~/repos/tachi/desktop/build/appicon.png`，用 `BADGE_AVATAR_SRC` 可以改。
换头像只改这一处：脚本会裁白边、缩到 120×120、把圆外涂成屏幕底色。

### 字体（已入库，通常不用管）

界面里的中文来自 tachi（会话标题、命令预览、模型提的问题），所以字体得覆盖**任意**常用
汉字——LVGL 内置的那个 CJK 子集小到连「脑」「还」「连」都不含，缺一个字就是一个方框。

字体产物**随仓库分发**（`main/badge_font_16.c` 约 18 MB、`main/badge_font_icon_16.c` 几 KB），
克隆下来直接就能构建。只有换字体、改字符范围、或改字号时才需要重新生成：

```bash
./tools/gen_badge_font.sh          # 源默认用依赖里自带的思源黑体（Source Han Sans SC，OFL）
```

源字体必须是**允许再分发**的：产物要提交，而 macOS 自带的中文字体（Arial Unicode、
Hiragino）授权不允许。要换就换 OFL 的：思源黑体 / Noto Sans SC。

同一个脚本还生成 `main/badge_font_icon_16.c`：顶栏那两枚**传输图标**（USB / 蓝牙）。
这两个 logo 在 Unicode 里没有码位，只能取图标字体的私有区字形（U+F287 / U+F293，
FontAwesome 的 brands 字形），所以脚本默认用 LVGL 组件里自带的那份 FontAwesome——
它跟依赖一起拉下来，授权文本在同一目录的 `font_license/FontAwesome5/`。要换别的图标
字体就设 `BADGE_ICON_FONT_SOURCE`。它单独一份、而不是并进中文字体，是为了缺了会响
——并进去的话缺字只会变成屏上一个方框。

## 目录

```
main/badge_proto.c    协议：一行 JSON 的解析与编解码（纯逻辑，主机上可测）
main/badge_json.c     上面那层用的极简 JSON 读写（零依赖、无动态分配）
main/badge_link.c     串口收发：分帧、只认带 @@ 的行
main/badge_ble.c      BLE 链路：GATT peripheral、配对与四态状态、主动断开卡住的连接
main/badge_state.c    状态机：收到什么、按键该发什么（纯逻辑，主机上可测）
main/badge_power.c    屏幕亮灭：空闲多久熄、什么该点亮（纯逻辑，主机上可测）
main/badge_ui.c       四块屏（自己的界面，不是基线的 demo 菜单外壳）
main/main.c           入口：初始化、事件循环、心跳与超时
tests/test_badge_*.c  上面那些纯逻辑部分的单元测试（`./tools/validate.sh --static` 会跑）
```

## 已知约束

- **LVGL 的字体位图索引默认只有 20 位（1MB）**。这份字体有两万多个字形，超过上限，
  所以 `sdkconfig.defaults` 里开了 `CONFIG_LV_FONT_FMT_TXT_LARGE`。不开的话编译会报
  `-Woverflow`，索引被截断成低 20 位、字体表全乱——看起来像是字体生成错了。
- **改 `sdkconfig.defaults` 后必须删掉 `sdkconfig`** 再构建：defaults 只在生成配置时生效，
  已存在的 `sdkconfig` 不会跟着变。
- **生成字体时必须加 `--no-compress`**。`lv_font_conv` 默认给位图做 RLE 压缩并在描述符里
  写 `bitmap_format = 1`，而那个格式是 LVGL 8 时代的，LVGL 9.5 解不出来。它的表现极具
  欺骗性：字形查得到、边界框尺寸也对，但屏幕上什么都不画；换成内置字体又一切正常。
  于是很容易误判成「字体太大」「内存不够」或「渲染层坏了」。
  （`tools/gen_badge_font.sh` 已经带上了这个参数。）
- **换电脑不是插上就能用**：这边存的 bond 和电脑上那份是两份，**只忘一边的结果是「连上即断」，
  而且 macOS 不会自己重新配对**。要换电脑，先在状态屏上长按确定两次忘掉本机，再去系统设置的
  蓝牙里 Forgot 那台设备（CoreBluetooth 没有 unpair API，那是唯一的补救路径）。
- 串口是独占的：这个固件跑着的时候，`idf.py monitor` 打不开同一个口。
